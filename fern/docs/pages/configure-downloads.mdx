---
title: 配置下载与上传 / Configure downloads and uploads
slug: configure-downloads
---

此功能为源码构建的受限预览，尚无可安装的产品发行版。下文的 download 模式只读取已经准备好的 local/generic 仓库与制品；不会创建数据库表、账户或授权，也不启用上传或账户管理接口。首次使用前，请让管理员准备数据库、仓库、读授权和制品目录。
Download mode in this source-build preview reads existing local/generic repositories. Ask your administrator to provision the database, accounts, read grants and stored artifacts first. Download mode does not bootstrap accounts or enable uploads.

## 构建二进制 / Build the binary

使用 [BinFlow 源码仓库](https://github.com/0ldlight/bf)中包含下载模式的源码，在仓库根目录使用 Go 1.27.1 或更高版本构建。下文的命令假设当前目录中已有构建出的 binflow；这不是正式发行包。
Build from the [BinFlow source repository](https://github.com/0ldlight/bf) with Go 1.27.1 or later. Run this in the source repository root; the following examples use the resulting local binary.

```sh
go build -o binflow ./cmd/binflow
```

## 默认健康模式 / Default health mode

直接启动 `binflow` 只开放健康检查，默认监听 `127.0.0.1:8080`。`BINFLOW_LISTEN_ADDR` 可以改变健康模式的监听地址。健康检查成功不代表下载模式已启用。
Running `binflow` without selecting a mode serves health checks only. A successful health check does not mean downloads are enabled.

## 下载配置 / Download configuration

将配置保存在运行 BinFlow 的用户所拥有的普通文件中，权限设为 `0600` 或只读的 `0400`。使用绝对路径；配置文件不能是符号链接，不能超过 16 KiB。不要把真实配置提交到代码库或贴入聊天、工单。
Use an owner-only regular configuration file and an absolute path. Keep its credentials out of repositories and support messages.

```json
{
  "listen_addr": "127.0.0.1:18080",
  "postgres_dsn": "<由管理员提供的完整 PostgreSQL 连接 URL>",
  "filestore_root": "/absolute/path/to/filestore",
  "repo_key": "generic-local",
  "challenge": "Basic realm=\"BinFlow\"",
  "failure_threshold": 3,
  "failure_window_seconds": 60,
  "block_seconds": 60,
  "max_tracked_users": 4096
}
```

九个字段均必需；未知、重复字段或无效值会使启动失败。`repo_key` 必须是已配置的 local/generic 仓库。失败次数为 1–100，窗口和阻断时间为 1–3600 秒，跟踪用户上限为 1–4096。
All nine fields are required. Unknown or duplicate fields fail startup. Repository and permission data must already exist.

数据库连接 URL 必须明确包含单一主机、端口、用户、非空密码、数据库及 `sslmode`，可选 `search_path`。字面量回环数据库可使用 `sslmode=disable`；远端数据库只支持使用系统 CA 的 `sslmode=verify-full`。本预览不支持多主机、服务文件、密码文件、在连接 URL 中指定 CA 文件或客户端证书。若数据库 CA 不在默认信任集合中，请让管理员准备并验证该服务使用的信任集合；不要关闭证书链或主机名校验。
Use a complete single-host PostgreSQL URL. Plaintext database connections are restricted to literal loopback addresses; remote connections require hostname-verified TLS using the service’s configured system trust pool. An administrator must provision and verify any additional trusted CA; CA-file URL parameters are not supported.

若管理员确认连接需要禁用语句缓存，可在 URL 中显式增加 `default_query_exec_mode=exec`；仅接受 `exec`，空值、其他值或重复参数会使启动失败。不设置时保留默认行为。此选项不保证任意事务连接池均可使用；管理员仍须验证实际连接池的 schema 隔离与权限行为。
If your administrator requires uncached execution, add `default_query_exec_mode=exec` to the URL. Other, empty or duplicate values fail startup. The option alone does not establish compatibility with a transaction pooler.

下载模式拒绝已有的 `PG` 前缀环境设置，避免数据库连接参数被其他工具的环境补充。请通过独立的服务环境启动，并把全部数据库设置放入受控配置文件。
Start downloads in a dedicated service environment without ambient `PG` settings.

## 启动与停止 / Start and stop

下载模式使用 JSON 中的监听地址，不能同时设置 `BINFLOW_LISTEN_ADDR`。
Download mode takes its listener from JSON; do not also set `BINFLOW_LISTEN_ADDR`.

```sh
unset BINFLOW_LISTEN_ADDR
BINFLOW_MODE=download \
BINFLOW_DOWNLOAD_CONFIG=/absolute/path/to/download.json \
./binflow
```

下载监听仅接受字面量回环 IPv4/IPv6 地址。外部访问须由管理员配置并验证 HTTPS 入口；不要将 Basic 认证直接开放到公网明文 HTTP，也不要依赖转发头改变这个限制。
Downloads bind only to a literal loopback address. Use an administrator-managed HTTPS entry point for external access.

等待日志出现 `binflow: listening on ...` 后再访问。配置、数据库、安全数据或仓库不完整时，进程会非零退出，不会退回健康模式。发送 `SIGTERM` 或 `SIGINT` 可停止服务；正常停止会等待在途请求。排空超时会中止连接并非零退出，请勿把它当作成功完成的下载。
Wait for the listening message. Incomplete configuration fails startup. Signals initiate graceful shutdown; a drain timeout aborts connections and exits with failure.

## 下载与常见响应 / Downloads and responses

仅支持已有 ASCII 路径上的精确小写 `.bin`、`.txt`、`.json` 文件，方法为 GET 和 HEAD。Basic 使用已配置的用户名和密码；可让 curl 交互式提示密码，避免把密码放入命令参数。
Only existing ASCII paths with exact lowercase `.bin`, `.txt` or `.json` extensions support GET and HEAD. Let curl prompt for the password.

`.json` 文件的下载 Content-Type 为精确的 `application/json`。类型按最终后缀确定：`a.json.txt` 仍为 `text/plain`，`a.txt.json` 为 `application/json`。服务器将正文视为原始制品字节，不解析或验证 JSON；空正文与非 JSON 字节同样原样保存和下载。
A `.json` download has exactly `Content-Type: application/json`. The final suffix determines the type: `a.json.txt` remains `text/plain`, while `a.txt.json` is `application/json`. Bodies remain opaque artifact bytes, without JSON parsing or validation; empty and non-JSON content is stored and downloaded unchanged.

```sh
curl --user "$BINFLOW_USER" \
  http://127.0.0.1:18080/artifactory/generic-local/dir/a.bin \
  --output a.bin

curl --user "$BINFLOW_USER" --head \
  http://127.0.0.1:18080/artifactory/generic-local/dir/a.bin
```

| 响应 / Response | 说明 / Meaning |
| --- | --- |
| 200 | 下载成功；HEAD 仅返回表示头，不返回文件字节 / Success; HEAD has no file body |
| 401 | 缺失或无效凭据 / Missing or invalid credentials |
| 403 | 缺少 read 授权，或同一用户名已被临时阻断 / Read denied or temporary authentication block |
| 404 | 仓库或文件缺席，或不属于此服务配置的仓库 / Missing or unserved repository/file |
| 400、405、501 | 路径、方法或功能超出当前支持范围 / Unsupported request profile |
| 500 | 数据库或存储故障；请联系管理员 / Database or storage failure |
| 503 | 服务正在停止 / Service is stopping |

此预览不支持匿名、Bearer、部分下载 Range、条件请求、查询参数、复杂路径授权或完整 Artifactory API 兼容。组或直接 read 授权变更在后续请求重新核实；已经获准的在途传输可能完成。
Anonymous/Bearer access, ranges, conditional requests, queries and broader API compatibility remain outside this preview.

## 普通上传 / Ordinary uploads

管理员必须显式启用 `BINFLOW_MODE=artifacts` 并准备上传配置及授权，才能使用普通 PUT；上文的 download 配置不能直接用于此模式。普通 PUT 是源码构建的受限预览；请先向管理员确认目标入口已启用，并为你的账户授予所需权限。
Your administrator must explicitly enable `BINFLOW_MODE=artifacts` and prepare upload configuration and permissions before ordinary PUT can be used. The download configuration above is insufficient for this mode. Ordinary PUT is a limited source-build preview. Confirm with your administrator that the target endpoint is enabled and your account has the required permissions.

上传仅支持已配置 local/generic 仓库中的受限 ASCII 路径，扩展名必须为精确小写 `.bin`、`.txt` 或 `.json`。请使用管理员提供的 HTTPS 入口与专用测试路径。已验证的 UAT 环境将单次正文限制为 1 MiB（1,048,576 字节）；其他环境的上限请向管理员确认。
Uploads support restricted ASCII file paths with exact lowercase `.bin`, `.txt` or `.json` extensions in the configured local/generic repository. Use the HTTPS endpoint and dedicated test path supplied by your administrator. The verified UAT environment limits each request body to 1 MiB (1,048,576 bytes). Ask your administrator for the limit in other environments.

准备普通文件 `a.json`，设置 `BINFLOW_BASE_URL` 为管理员提供的入口、`BINFLOW_USER` 为应用用户名。curl 会交互式提示 Basic 密码，不要将密码放入命令参数。
Prepare a regular file named `a.json`, set `BINFLOW_BASE_URL` to the administrator-provided endpoint and `BINFLOW_USER` to your application username. Let curl prompt for the Basic password; keep passwords out of command arguments.

```sh
SHA256=$(shasum -a 256 a.json | awk '{print $1}')

curl --include --user "$BINFLOW_USER" \
  --header "X-Checksum-Sha256: $SHA256" \
  --header 'Expect:' \
  --upload-file a.json \
  "$BINFLOW_BASE_URL/artifactory/generic-local/dir/a.json"
```

`X-Checksum-Sha256` 可选；提供时必须恰为一个由 64 个小写十六进制字符组成的摘要，并与正文一致。请求必须有已知的 Content-Length；示例由 curl 从普通文件计算长度。不支持分块传输、查询参数、条件请求或 checksum-deploy。
`X-Checksum-Sha256` is optional. When supplied, it must contain exactly one 64-character lowercase hexadecimal digest matching the body. Content-Length must be known; curl derives it from the regular file in this example. Chunked transfer, query parameters, conditional requests and checksum-deploy are unsupported.

每次上传都需要 deploy 授权。新路径不需要 delete；覆盖已有文件时，若 SHA1 和 SHA256 均未提供，或任一已提供摘要与已有文件不一致，还需要 delete。当前 artifacts 模式下，至少提供其中一种摘要且所有已提供的这两种摘要均一致时，不需要 delete。仅提供 MD5 不能免除 delete。这里的 delete 是覆盖权限，不表示提供 HTTP DELETE 接口。提交时会重新检查授权与目标状态。
Every upload requires deploy permission. A new path does not require delete. For an existing file, delete is also required when both SHA1 and SHA256 are omitted or any supplied SHA1/SHA256 differs from the stored file. In the current artifacts mode, delete is unnecessary when at least one of those digests is supplied and all supplied SHA1/SHA256 values match. MD5 alone does not waive delete. Here, delete is an overwrite permission, rather than an HTTP DELETE endpoint. Permissions and target state are checked again at commit.

| 响应 / Response | 说明 / Meaning |
| --- | --- |
| 201 | 保存已提交；返回制品元数据、Location 和实际 X-Checksum-Sha256 / Committed; returns artifact metadata, Location and the actual X-Checksum-Sha256 |
| 401 | 缺失或无效凭据，或账户已禁用 / Missing or invalid credentials, or disabled account |
| 403 | 缺少 deploy 或所需的 delete、用户名临时阻断，或提交复查拒绝 / Missing deploy or required delete, temporary authentication block, or commit-time denial |
| 409 | 正文与声明的长度或摘要不一致；不是“目标已存在” / Body differs from the declared length or checksum; an existing target alone does not cause this response |
| 400 | 路径、摘要格式或请求正文无效 / Invalid path, checksum format or request body |
| 411 | 正文长度未知 / Unknown Content-Length |
| 413 | 正文超过配置上限 / Body exceeds the configured limit |
| 405、501 | 方法或请求功能超出支持范围 / Unsupported method or request feature |
| 500 | 数据库或存储故障 / Database or storage failure |

启用后，在管理员分配的测试路径确认：不带认证为 401；有效账户缺少 deploy 为 403；有 deploy 的新文件为 201；在另一个新路径提供格式有效但与正文不同的摘要为 409。成功后使用有 read 授权的账户下载，核对字节与摘要。相同摘要重传应为 201；无 delete 的不同内容覆盖应为 403，补充 delete 后应为 201，撤销 deploy 后应为 403。已有文件的上传被拒绝后，重新下载并确认原文件未改变。
After activation, use the assigned test path to confirm: no authentication gives 401; valid credentials without deploy give 403; a new file with deploy gives 201; a well-formed digest differing from the body at another new path gives 409. After success, download with a read-authorized account and compare the bytes and digest. A matching-digest retry should give 201; different content without delete should give 403, then 201 after delete is granted, and 403 after deploy is revoked. After a denied upload to an existing file, download again to confirm the previous file is unchanged.
